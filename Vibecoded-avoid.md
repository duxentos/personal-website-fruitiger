# Anti-Vibe-Coded Website Design Constraints

## Objective

Build a distinctive, intentional, professionally engineered website that does not resemble a generic AI-generated landing page.

Every design choice must serve a purpose. Prioritise originality, visual personality, usability, and consistency.

The website should feel handcrafted rather than assembled from common AI UI patterns.

## 1. No Excessive Emojis

**Avoid:**
- Emojis as navigation icons.
- Emojis in section headings.
- Emojis inside every project card.
- Emojis as decorative substitutes for proper illustrations.
- Random rockets, fire, lightning bolts, brains, and sparkles.

**Instead:**
- Use a consistent icon library.
- Create custom SVG icons where appropriate.
- Use authentic retro desktop iconography.
- Maintain consistent icon sizes, stroke weights, and visual treatments.

Exception: Emojis are acceptable when deliberately part of a project's identity or content.

## 2. Avoid Generic AI Landing Page Layouts

Do not automatically build a website containing:

1. Giant centred hero heading.
2. Gradient-highlighted buzzword.
3. Two oversized CTA buttons.
4. Three feature cards.
5. Testimonial section.
6. Generic FAQ accordion.
7. Massive footer.

Use layouts appropriate to the actual content.

For this portfolio, prefer an interactive desktop, project explorer, or application-inspired layout.

## 3. No Generic AI Copywriting

Avoid phrases such as:

- "Crafting digital experiences"
- "Where innovation meets creativity"
- "Transforming ideas into reality"
- "Building the future, one line of code at a time"
- "Passionate about leveraging cutting-edge technologies"
- "Seamlessly bridging technology and innovation"
- "Explore my journey"
- "Unlocking endless possibilities"

Use natural, specific, technically grounded language.

Describe what a project does, why it exists, and how it was built.

Do not invent achievements or exaggerated claims.

## 4. Avoid the Default AI Colour Palette

Do not default to:

- Purple-to-blue gradients.
- Dark navy backgrounds with glowing purple orbs.
- Identical cyan accents everywhere.
- Black-and-white SaaS minimalism.
- Generic pastel cards.

Instead, use the established Frutiger Aero colour system with deliberate variety.

Use vibrant aqua, cyan, green, orange, yellow, coral, pink, and violet where appropriate.

Colour choices should have clear visual roles.

## 5. No Generic Rounded Card Grids

Avoid filling every page with identical rounded rectangles.

Common AI-generated patterns include:

- Three equally sized cards in every section.
- Identical padding and shadows everywhere.
- Repeated icon-heading-description cards.
- Excessively large border radii.
- Endless glassmorphism panels without hierarchy.

Instead, create visual variety through composition, scale, layout, and content.

Use different project presentations when their content genuinely differs.

## 6. No Meaningless Animations

Avoid:

- Every element fading in on scroll.
- Excessive floating objects.
- Constant glowing and pulsing.
- Overly springy buttons.
- Unnecessary parallax.
- Animated gradients on every component.
- Hover effects that move elements excessively.

Animations must communicate interaction, feedback, navigation, or hierarchy.

Respect reduced-motion preferences.

## 7. No Fake Functionality

Never create:

- Buttons without actions.
- Search bars that cannot search.
- Non-functional theme toggles.
- Fake notification indicators.
- Placeholder social links.
- Decorative terminal commands that pretend to execute.
- Fake loading screens.

If an element looks interactive, it must behave interactively.

## 8. No Unnecessary UI Libraries

Do not install large component libraries simply to generate a basic website quickly.

Avoid copying complete prebuilt landing pages.

Use libraries when they provide meaningful accessibility, behaviour, or development benefits.

Build custom components for the website's distinctive visual identity.

## 9. Avoid Generic Typography

Do not automatically use Inter for everything.

Avoid:

- Enormous bold headings everywhere.
- Excessive uppercase labels.
- Gradient text in every section.
- Too many font weights.
- Generic centred paragraphs.

Use a coherent typography system inspired by Segoe UI, early Apple interfaces, and classic desktop applications.

Prioritise readable text and consistent spacing.

## 10. No Artificial Complexity

Avoid:

- Unnecessary backend services.
- Authentication for a static portfolio.
- Over-engineered state management.
- Excessive component abstractions.
- Dependencies for trivial CSS effects.
- Huge files containing multiple unrelated components.
- Unnecessary AI integrations.

Implement the simplest architecture that meets the actual requirements.

## 11. No Fake Technical Credibility

Never invent:

- GitHub statistics.
- Project performance metrics.
- User counts.
- Professional experience.
- Technology stacks.
- Awards.
- Testimonials.
- Deployment status.

All portfolio information must reflect real work.

Clearly label experimental or in-progress projects.

## 12. Avoid Repetitive Design

Do not make every section visually identical.

Avoid repeating the same:

- Card layout.
- Heading style.
- Background gradient.
- Animation.
- Icon treatment.
- Content structure.

Create a unified visual language without sacrificing variation.

## 13. No Overused Developer Portfolio Tropes

Avoid automatically adding:

- "Hello World" hero headings.
- Fake terminal introduction screens.
- Matrix-style falling code.
- Random code snippets as decoration.
- Unnecessary typing animations.
- Fake GitHub contribution graphs.
- Generic spinning 3D globes.
- Tech stack logos floating around the screen.

These features are only acceptable if they serve a meaningful purpose in the design.

## 14. Frutiger Aero Specific Rules

The interface should take inspiration from genuine 2000s software design rather than modern SaaS glassmorphism.

Prioritise:

- Glossy surface highlights.
- Multi-layered gradients.
- Reflections.
- Subtle skeuomorphism.
- Distinctive application-style windows.
- Functional desktop icons.
- Thoughtfully designed navigation.
- Authentic desktop-inspired interaction patterns.
- Carefully balanced vibrant colours.

Do not simply add `backdrop-filter: blur()` to every rectangle and call it Frutiger Aero.

Glass surfaces should have believable depth through borders, lighting, shadows, reflections, and tonal variation.

## 15. Quality Assurance

Before considering a page complete, ask:

1. Does this look like a generic AI-generated website?
2. Are emojis being used instead of proper icons?
3. Does every interactive element work?
4. Is the writing specific rather than full of buzzwords?
5. Is the layout appropriate for the actual content?
6. Are the animations necessary?
7. Does the design have a recognisable identity?
8. Could this page belong to hundreds of other portfolios?
9. Is the website accessible and responsive?
10. Does the interface feel intentionally designed?

If a component looks generic, redesign it rather than applying more gradients or animations.

## Final Rule

**Do not optimise for how quickly a plausible website can be generated. Optimise for how thoughtfully the finished website appears to have been designed.**

The final result should feel like a distinctive, handcrafted Frutiger Aero portfolio created by an engineer with a strong interest in both software and interface design.
